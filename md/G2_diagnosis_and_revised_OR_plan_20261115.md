## 一、核心结论速览

   - **关于“先冻结初乘取消与在车条件校准的分别定义”**：我们已直接从 `natural_gap_v2/calibration_summary.json` 通过代数恒等式**精确无损**拆出了剔除 2 辆初乘取消车（19 项未发生事件）后、全部 `1,309` 项真实已上车事件的条件校准结果（无需重拉服务器原始数据）。结果显示：**`P10`（上游赶上、下游错失）的条件均值残差高达 `+0.0312`（`+3.12%`，机会加权 `+3.31%`，14 天中有 13 天为正，4 类 Bonferroni 95% 区间 `[+0.0165, +0.0467]`），`P00` 均值为 `-0.0219`（区间 `[-0.0361, -0.0091]`），`P01` 区间为 `[-0.0249, -0.0034]`**。也就是说，即使 100% 拆走初乘取消，**点估计本身就已经突破 `±0.02`**，原校准门依然不可能通过；且按 Codex“已暴露日期不可改判据”的规则，还会被迫再去抓第 4 批 14 个新日期重复同一死局。

## 二、对 Codex 下一步建议的逐项定量核验

Codex 建议的核心动作是：*“保留修复候选、扩展菜单和原预算，先冻结初乘取消与在车条件校准的分别定义，核实三个正事件组及负例的站台证据，同时检查下车点与尾车选择耦合的结构和新颖性……一次性做完，再决定是否值得深度重构，继续解决 G2。”*

我们利用仓库现有冻结收据对其每一项做了严格数学核验（详见 [`OFFLINE_AUDIT_SUMMARY.json`](../experiments/g2_reset_v1/OFFLINE_AUDIT_SUMMARY.json)）：

### 2.1 核验一：拆分初乘取消后，在车条件校准能否通过原校准门？—— **不能，且证明存在系统性物理偏差**

在 `natural_gap_v2` 的 `1,328` 项注册换乘事件中，仅 `2023-04-04`（`root 151`，S24 取消，3 项事件）和 `2023-04-05`（`root 160`，S20 取消，16 项事件）因首乘列车取消而未到达首个在车决策点。其余 `1,309` 项事件模型与真实标签 **100% 完整解析**。

由于未到达事件在 `calibration_summary.py` 中对四个分区均赋予对称区间 `[-1, +1]`，每个事件组的精确已解析残差之和满足代数恒等式 $S_k = N \cdot (\text{lo}_k + \text{hi}_k) / 2$（且满足宽度恒等式 $\text{hi}_k - \text{lo}_k = 2U/N$ 与概率守恒 $\sum_k S_k = 0$，机器精度误差 $< 10^{-12}$）。精确提取结果与 `decision_calibration_v2`（`2023-03-09` 至 `03-22`）对比如下：

| 面板（已剔除初乘取消，仅在车条件事件） | 已解析事件数 | `P00` 均值残差 `[Bonf 95% CI]` | `P01` 均值残差 `[Bonf 95% CI]` | `P10` 均值残差 `[Bonf 95% CI]` | `P11` 均值残差 `[Bonf 95% CI]` | 4类 Brier (Skill) | 原 `±0.02` 门结论 |

**关键发现**：
1. 两组完全独立的 14 天样本呈现出**惊人一致的物理结构**：`P10`（“上游可赶上、下游 Zürich HB 错失”）在现实中发生的频率比 `P0` 模型预测高出 **`+3.12%` 至 `+3.25%`**（在 `forecast_age <= 300s` 即已有实时预测时甚至高达 **`+4.15%`**！）。
2. 原因非常清楚：早高峰 08:00 前后驶入 Zürich HB 咽喉区的进站区段存在强正偏的咽喉排队延误，全天无条件拟合的段间转移核系统性低估了最后一段进站晚点尾部。
3. 更致命的是，这一 `+3.1%` 的 `P10` 偏差**直接制造了求解器的负例**：在 `control_identity_v1` 的 `R09 (-329s)` 和 `R18 (-145s)` 中，`full128` 正是因为相信模型低估后的 `P10` 风险，把 `cheap` 在上游 Oerlikon 安全换乘的动作改成了继续坐去 Zürich HB，结果在 HB 真实错失换乘！
4. 同时，用 $N=14$ 个日期簇做 4 分区联合 98.75% Bonferroni `±0.02` 等价检验，标准误本身约 `0.0055–0.0079`，即便真实偏差仅 `0.008` 也会频繁跨过 `±0.02`。**把这一统计欠功效且违背 `.docx` 原意（“任意条件风险都已校准不应成为 OR 验收目标”）的二元门留在前置位置，只会让项目永远卡死。**

### 2.2 核验二：2023 瑞士公开档案能否核实“实际物理站台”？—— **档案无此字段，但公开/声明站台对已 100% 明确**

1. **物理实际站台不可得**：`natural_gap_v2/actual_filter_summary.json` 记录了 2023 年 `ist-daten` 原始表头（共 21 列）：仅有 `BPUIC`（车站级 UIC 编码）和到发实际时刻，**不含任何物理站台/股道字段**；GTFS-RT 亦无瑞士列车位置流。继续去核实“正负例实际物理停靠股道”在 2023 公开数据上不可能完成。
2. **相反，现有 `gtfs_station_max = 420s` 合同的人为失真已经板上钉钉**：
   - 对 `2,656` 个注册换乘对审计可见：**`1,156` 对（`43.5%`）在静态 GTFS `transfers.txt` 中有精确站台对换乘秒数**，而其余 **`1,500` 对（`56.5%`）全部是同物理站台换乘**（如 Zürich HB 地下贯通式站台 `8503000:0:41/42 -> 8503000:0:41/42` 或 Stadelhofen `8503003:0:2 -> 8503003:0:2`）！两者合计覆盖率达 **`100.0%`**。
   - 在 `natural_gap_v2` 收到的 `4,234` 条实时站台声明中，**`4,211` 条（`99.46%`）与静态计划站台完全一致**（14 天中有 11 天为 100% 零变更，含 `R004` 所在的 `03-23` 与 `R098/099` 所在的 `03-31`）。
   - 现行模拟器对在同一个岛式站台 `41/42` 原地换乘的旅客强行收取 **`420 秒`（7 分钟！）** 全站最大跨区步行时间，比合理同站台缓冲（`90 秒`）多罚了 **`330 秒`（5.5 分钟）**！这直接扭曲了“留车去 HB 同台换乘 vs 提前在 Oerlikon/Hardbrücke 下车”的真实优劣。

## 三、深度代码审计：卡在 G2 的五大底层机制

通过对 `src/onboard_stopping.py`、`reconstruction_v38..v51` 及 `decision_gap_v1`..`natural_gap_v2` 的逐行核查，我们把全部现象收敛为五条精确机制：

### 机制 1：两出口链上的代数坍缩（解释为何 `cheap == single == pair == one_step` 在 238/238 趟完全同分）
在 [`src/onboard_stopping.py`](../src/onboard_stopping.py) 第 139–161 行中，当剩余下车出口数 $m \le 2$（如 Oerlikon 与 HB、HB 与 Hardbrücke、Stadelhofen 与 Hardbrücke）时：
- 末站 $r=1$ 满足 `optimal_values[1] == fixed[1][1] == rolling.values[1] == alight_costs[1]`；
- 首站 $r=0$ 的 `optimal`、`rolling_fixed` 与 `one_step_rollout` 比较的完全是同一个数组：`alight_costs[0]` 对 `_continue(0, alight_costs[1])`！
因此，在绝大多数两出口决策上，`one_step_rollout` 花了 `3.5 倍` CPU（`3.93s` vs `1.14s`），算出的却是与 `cheap` 在代数上 **15 位有效数字完全相等**的同一个数，根本没有对换乘站内部多车竞争做一步展开。

### 机制 2：`MatchedContinuationPlanner` 的单层截断与静态近似（解释 `natural_gap_v2` 三个正事件组 `57, 98/99, 136`）
在 [`experiments/reconstruction_v41/matched_continuation.py`](../experiments/reconstruction_v41/matched_continuation.py) 第 137 行：
```python
self.tail_base = PhysicalPlanner(graph, model, parameters, deadline)
```
`MatchedContinuationPlanner` 只对**第一次换乘**计算 `min(first_offer, single_target)`，而子乘车段的后续换乘全部退回 `PhysicalPlanner`（即纯 `first_offer` 首车盲乘！），且未使用同文件第 16 行已实现的精确 `FrozenCombinedReference`。
- 在 **`root 57`（省 247 秒）** 中，Oerlikon 下车方案是**两次换乘**（`S21 -> Hardbrücke -> S5`），HB 下车方案是**一次换乘**（`IR36 -> HB -> S12`）；单层 `tail_base` 导致两跳分支与精确 `Combined` 估值失配。
- 在 **`roots 98/99`（共享同一尾车事件，省 83 秒）** 与 **`root 136`（省 240 秒）** 中，上游站与下游站之间存在跨站到达时刻演化与多目标 `Combined` 等待竞争，静态边际包络 `min(first_offer, single_target)` 未捕获到达第二站时的条件状态更新。

### 机制 3：`matched.py` 第 136 行的 `1e-9` 未认证蒙特卡洛噪声覆写 Bug（直接造成 `-403 秒` 无谓损失！）
在 [`experiments/reconstruction_v44/matched.py`](../experiments/reconstruction_v44/matched.py) 第 134–138 行（被 `v51/run.py` 直接调用）：
```python
ACTION_TIE_SECONDS = 1e-9
def choose(result, base):
    low, high = result['paired']['full_bank_mean_gain_interval']
    return ('alight' if high < -ACTION_TIE_SECONDS else
            'continue' if low > ACTION_TIE_SECONDS else base)
```
当 128 个抽样世界全部完结时，`full_bank_mean_gain_interval` 退化为点估计 `[mean_gain, mean_gain]`，**完全不含蒙特卡洛标准误 `se`**！只要样本均值偏离 0 超过 `10^-9` 秒，控制器就强行推翻解析策略 `base`！
- 在 `control_identity_v1` **`R04`（亏 263 秒）** 中：解析策略以 `+79.9 秒` 明确支持 `continue`，128 世界均值仅 `-2.34 秒`，标准误高达 `16.89 秒`（**`t = -0.14`，95% CI `[-35.5, +30.8]`**），纯属抛硬币噪声，却被 `< -1e-9` 强行翻转为 `alight`！
- 在 **`R32`（亏 140 秒）** 中：解析策略以 `-145.4 秒` 支持 `alight`，128 世界均值 `+11.72 ± 24.96 秒`（**`t = +0.47`，95% CI `[-37.2, +60.6]`**），同样因纯抽样噪声被翻转为 `continue`！
仅用配对置信区间认证（[`choose_certified`](../experiments/g2_reset_v1/certified_gate.py)）即可**零成本消除这两起合计 `-403 秒` 的噪声事故**。

### 机制 4：无差别全门调用 + 静态菜单宽度判断失误（解释为何 CPU 暴涨至 `49.01 秒`）
1. **无裕度过滤**：[`reconstruction_v51/run.py`](../experiments/reconstruction_v51/run.py) 第 36 行在**每一个有后续出口的在车决策点**无条件启动 128 世界回放（`natural_gap_v2` 共 `328` 个门，`control_identity_v1` 共 `136` 个门）。但离线审计显示，`136` 个门的中位解析差高达 **`342.6 秒`**，**`71.3%` 的门解析优劣差距超过 `120 秒`**（最高 `1,096.7 秒`），跑 128 世界完全是白烧 CPU。
2. **静态宽度误判**：[`reconstruction_v51/rollout.py`](../experiments/reconstruction_v51/rollout.py) 第 54–58 行用静态扩展菜单总车次数 `len(p.rides) <= 6` 判断是否允许快速局部核 `V45_canonical_prefix_kappa`。前缀闭包扩展后，Zürich HB 静态菜单常含 12–22 辆车（其中大半在当前时刻 `entry` 前早已发车，剩余存活概率为 0！），导致 **`287 / 328`（`87.5%`）的门被迫退回全观测慢回放 `full_common_observation_pi`**，并在 128 个世界的每个站台观测时刻反复触发精确锚点马尔可夫链重建，单门最高耗时达 **`57.88 秒`**！

### 机制 5：固定候选菜单对全图重规划的限制（被忽视的重要发现）
在 `natural_gap_v2` 中，仅需 **`0.54 秒` CPU** 的确定性全图扫描基线 `MeanSnapshotCSA` 在 **6 个根（`roots 6, 20, 78, 135, 140, 150`）上同时击败了 `cheap` 和 `full128`**，合计省下 **`536 秒`**（仅在 `root 53` 因确定性均值盲目冒险亏 `993 秒`）。这证明：**V50 冻结的初始候选菜单之外仍存在真实可行的全图替代班次**，而耗费 49 秒的 `full128` 因为被关在初始声明尾车集合内，对这 6 个根完全无能为力。
