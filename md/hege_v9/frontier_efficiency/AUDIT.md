## 结论与边界

本次已经实现并核验一个审计用增量前沿：保留朴素 A-global 消融的选择规则，使用增量根概率传播和版本化优先堆代替每次付费前的全图扫描。仅运行了 **manifest 55 / root27 一次**。同样 2000 次收费、同样 120 CPU 秒上限和 A/C/A 分配模板下，最终动作收据与朴素原型逐字段相同，差区间为 **[20.24841151059809, 20.24841151059809] 秒**，认证 CONTINUE。与原 query 口径一致的完整费用为 **7.739574 CPU 秒**，朴素原型为 **110.770241 CPU 秒**。

这证明该根上的朴素全图扫描开销可以大幅消除，且没有丢失该次调度获得的动作证书。它没有证明所有自然根都能认证，也没有把 best-first 调度当作新的 OR 理论贡献。自然根未扩展到其余六个。本次为回溯性机制审计，不能替换仓库 V47 的预先固定结果或把 0/7 改写成新正式结果。

原核、朴素和增量原型的记录是分开运行的，未做同机随机交错重复计时；下表费用比仅是留存收据之间的描述性比较。原核和朴素文件均未重跑。

## 固定规则、未改内容与源码位置

被审计仓库 HEAD 为 `6e46267b56656595d2f996bc206ab65c5ee222d8`。运行前、运行后 `git status --porcelain` 均为空。所有新代码、测试和收据位于本目录；没有修改仓库或其他代理的文件。

实现文件为 `efficient_priority.py`。它继承仓库 `BulkIncrementalOracle`，只增加调度状态和计时。P0 物理概率、W 策略分数、原 π 决策、物理区间、节点 reducer、收费单位、2000 限额、120 CPU 秒 oracle 上限、首段 60 CPU 秒和 A/C/A 模板均沿用原实现。

优先序与 `../theory_code/priority_probe.py` 对齐：

1. 仅 ALIGHT 以及独立小链中的 `policy` 使用全局前沿；CONTINUE 保持原 `_next/_walk` DFS。
2. 在选择付费节点前，展开当前普通物理图上全部可达、尚未展开的零收费算术节点。算术工作消耗真实 CPU，不能因不收费而被饿死。
3. 普通正概率边传播根到达质量。所有入边贡献相加，不取某个父亲、最大父质量或局部条件概率。
4. 每个未展开付费候选的优先权为根质量乘当前物理宽度。同分按 `self.nodes` 的创建顺序。
5. `BulkDPNode/TerminalDPNode` 是不透明物理候选，优先权为其根质量乘原 reducer 当前宽度。选中块后，其内部继续使用原 DFS。
6. bulk 的 0 权 children 是调度依赖，用于依赖失效、宽度重算和原 DFS；从不当作物理概率乘入根质量，也不删除。

没有截断极小概率，没有以宽度打印成 0 为完成标志，没有引入拿到证书立即停止的策略。运行仍完整消耗 2000 个收费单位。

## 增量传播为何不会漏掉多父质量

设普通已展开物理 DAG 的质量满足 `w(root)=1`、`w(v)=Σ p(u,v)w(u)`。节点只从未展开变为展开，新增物理边而不删除旧边。

一轮新增边 `u→v` 先向 v 注入 `p(u,v)×w_old(u)`。所有注入及根初始质量形成 delta 源，再沿更新后的物理图，在受影响的后继子图上拓扑传播。于是该轮每条新边同时得到父节点的旧质量和本轮新增质量；旧边只收到本轮新增质量。最后令 `w_new=w_old+delta`。这避免了先展开共享子图、后来新增父路径时漏传后继的错误。

每轮 delta 的受影响后继子图先统计入度再拓扑遍历。重复物理边按边数计入入度和质量；没有把同一 child 的第二条真实边删掉。`numpy.longdouble` 仅用于优先序质量计算，原物理 value 计算仍由仓库实现完成。

候选更新时增加版本并向堆压入新条目。旧条目在弹出时核验版本、展开状态和块 drained 状态；权重增加、块宽度下降都会产生新版本。共享 DAG 的浮点求和顺序可能与朴素全图拓扑法在机器精度处不同；本次没有声称所有图都能逐比特保持同一序列。六个小链的付费序列逐项完全一致，最大相对根质量差为约 `7.697e-20`；root27 的最终值和核心工作计数也完全一致。

对于不透明块，单独保留“某节点变化会影响哪些块”的 watcher。watcher 沿包括 0 权边的全部 value/scheduling 依赖登记。当 C 或另一个共享路径展开了该节点，相关块宽度失效，并在下一次前沿选择前调用原 reducer 重算。这些依赖不进入普通根概率传播。

## 复杂度、残余风险与可执行下一步

每轮更新只在新增结构和 delta 影响到的后继子图上传播。若该轮受影响子图是 `H_t`，传播工作为 `O(|V(H_t)|+|E(H_t)|)`，另外付出更新候选及堆条目的对数成本。总体为这些受影响工作量之和；**不主张总复杂度最坏线性**。多次新增父路径可以反复触及很大的后继区域。在最坏情形下，收益仍可能接近反复大图更新。

opaque watcher 的规模受 `(依赖节点, opaque块)` 对数影响，多个大块共享深后继时可能很大。块宽度仍用原 reducer，原 bulk 内部 DFS 没有改进。版本堆的低优先级过期项会积累，本次峰值已留存；更大问题可能需要有单独证据支持的堆压缩。根权重计算保留全部正路径，但有限精度/下溢的一般数值限制仍在；物理 value 图本身完全不受这些排序权重近似影响。

建议下一阶段先冻结该规则和实现，再由用户/主审计决定是否在原七根上统一做一次相同限额的复核，并同时报告每根首个保存证书、完整 query 成本、全冷启动成本和残余质量。该核验应把“选择顺序改变”与“数据结构优化”分层比较。此次没有执行这些新增自然运行，也没有据结果改规则或事后调参。
