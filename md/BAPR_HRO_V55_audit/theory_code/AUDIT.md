# V55 理论与代码独立审计

固定版本：`a2b82be9c3fc6b61e2a5826d7cd8691d39ff4491`。审计日期：2026-11-15。

审计范围：V52–V55 的完整策略目标、界传播、根预算、V55 语义约简、终端子集 DP、与 V53 impact 的组合；检查相应证明和测试，读取全部 b10 配对原始回执的计数，并对两个关键查询做只读 profile。未修改仓库，未追加原实验预算，未重新跑全量 1760 查询。

## 1. 核心判断

没有发现足以推翻 V55 已声明有限模型上下界的新增正确性缺陷。V55 新增五个测试文件本次独立复测 **156 项全部通过**。这支持实现与其限定合同相符，不是完整形式化验证，也不能把测试通过数视为 OR 贡献。

G2 未通过至少有四层原因，不能合并成一个“还不够快”：

1. **研究对象尚未锁定。** 新代码仍是参照求值器，未产生新控制器、未提供新的完整策略收益。当前最值得研究的关键根，便宜策略的完整损失仍未解决。
2. **所证明的分解绕开了关键耦合。** 被积掉的是无关评分尾和独立终端平台；七个关键根的立即下车平台全部是混合续程。物理车次独立，不意味着“位置＋可达动作＋观察更新＋W 评分”独立。
3. **计算任务和缺口定位任务存在错配。** 固定便宜策略求值仍求全部强制根动作；最优模式又有便宜策略不能使用的可行策略上界。于是“最优值界窄、便宜值界宽、首动作可认证、完整 regret 未解”完全可能同时成立。
4. **实现仍有明确的普通工程改进空间。** 概率组合先枚举再筛选，W 评分重建昂贵，终端内核不可抢占且未复用内部未完成状态，单观察组还构造并丢弃两个条件链。这些说明当前 0/88 不是问题本身不可解的证明；修复它们也不会自动产生独立算法贡献。

建议停止把“再优化该求值器”作为 G2 主线。允许一次有边界的诊断工具修整，目的只是找到便宜规则的真实决策缺口；只有缺口、结构定理、相对标准方法增量三者都有证据，才启动下一轮主算法重构。

## 2. 为什么最优界较窄，固定策略界反而很宽

### 2.1 根界对不同目标并不对称，这是数学上必要的

`experiments/reconstruction_v53/reference.py:28–85` 在全部模式初始化条件目的地松弛下界；只有 `mode == 'optimal'` 才搜索至多 16 条合法固定路线作为上界，并将搜索限制在查询 CPU 的 15% 内（49–58 行）。

设固定规则为 π，可行承诺路线为 ρ，则

\[
V^* \le V^\rho,
\]

所以 ρ 的值是最优值的合法上界。但不能推出

\[
V^\pi \le V^\rho.
\]

直接把这个上界贴给固定便宜策略会改变求值对象并可能产生假证书。当前代码没有犯这个错误。因此最优区间比便宜策略区间窄，不能解读成求最优天然比评估固定策略容易；目前上界工具对最优目标更有利。

### 2.2 大部分最优值信息来自根预计算

直接由原始 `root_bounds` 重算最优值的 `min lower/min upper`，得到：

| b10 原回执 | 最终最优值区间等于根预界 | 根预界已认证首动作 | 最终认证首动作 |
|---|---:|---:|---:|
| V53 impact | 88/88 | 30 | 40 |
| V55 priority | 84/88 | 30 | 40 |

V55 真正增加最优值信息的是 root 0、12、36、41 四个查询，其区间宽度分别由根预界的 617.13、232.01、68.20、370.88 秒减到 140.18、24.83、1.83、161.08 秒。其余 84 个最优值区间不动。不能把这解释为递归完全无用：它另收紧了竞争动作界，首动作证书从根预界的 30 增到 40。但它对“固定策略究竟损失多少”的推进很小。

建议未来表格必须加入“仅根预界”参照，并分开报告三个成果：最优值区间收紧、竞争根动作排除、固定策略完整损失收紧。一个平均 CPU 数字无法区分三种计算。

### 2.3 40 个最优首动作证书不是 40 个完整便宜策略证书

首动作证书比较的是 `U(s,a*) < min_b L(s,b)`；它只证明当前该选哪个动作，续程按目标模式解释。完整 regret 需要

\[
V^\pi(s)-V^*(s) \in
[\max\{0,L_\pi-U_*\},\max\{0,U_\pi-L_*\}].
\]

即便 π 的首动作等于最优首动作，π 仍可能在下一次换乘、等待或信息更新后选错。所以 40 个首动作均与便宜规则一致，既没有建立新策略优势，也没有证明便宜规则完整最优。

### 2.4 固定策略求值仍消耗预算计算未执行的根臂

`experiments/reconstruction_v52/reference.py:402–444` 先计算根 `cheap_action`，但随后对所有强制根动作按固定累计份额求值，最后仅取 `actions[cheap_action]` 作为固定策略值。

例如 onboard 根只有 ALIGHT/CONTINUE 时，cheapW 最终只需一个执行臂的完整值；现在也花预算算另一个强制动作，以保留根动作诊断。V54 回流是在这项协议之上补救，没有改为“只求固定策略实际执行臂”。这不是隐瞒或正确性 bug，是一个公开但与完整 regret 定位不完全匹配的任务设计。

可新增明确区分的两种参照 API：`evaluate_policy` 只求实际选择臂，`evaluate_forced_actions` 才求全部根动作。不得把改动后结果冒充与旧协议完全同一任务；若一个主结论同时使用两者，必须合计费用。这属于标准任务拆分，不是新算法。

## 3. V55 证明什么成立，什么仍不成立

### 3.1 目的地屏障约简的边界正确且必要

`THEORY.md:3–53`、`semantic.py:12–121` 将首个**根时刻未被公告屏蔽**的物理目的地之后的评分出口删去，依据有序时间支撑、非负换乘时间、截断损失与非负核的保序性。它保持 rolling_fixed 的前缀动作和评分，不改物理菜单。

代码保留整条同车概率链、目的地后的已收到预测似然和原 schedule ranks。后槽证据能反向影响前槽分布，不能因到目的地即吸收而删去。masked goal、nominal 插值都有反例；测试确实包含这些限制。

该命题依赖冻结未来公共帧：之后硬观察可以解除已存在 mask，但没有新公共发布重新创建 mask。若将来引入动态服务公告过程，必须重审屏障的持续有效性，不能把当前证明直接外推。

### 3.2 终端子集状态充分，但条件非常强

`TERMINAL.md:3–24`、`terminal.py:228–245` 要求：每个候选的首个保留出口就是目的地；各候选来自不同车次；其评分只读取本车；相关现场观察恰好是候选根 departure。满足后才能用 `(时间, 未见候选集合, 决策深度)` 作为充分状态。

三种量不能混成一个 mark：

- 实际 BOARD 损失：固定根 P0 下整条同车后验积分。
- WAIT 分数：原 combined 规则的条件等待比较。
- 可见 departure 之后的 BOARD 分数：更新硬观察并触发 W 的原消息选择器，再评分。

代码按这三个定义分开实现（`terminal.py:37–59,128–158,195–217`）。这也是为何简单说“用每车一个到达均值即可分解”会改变策略。

### 3.3 80.69% 是结构菜单覆盖，不能替代概率质量、CPU 或根宽度贡献

`STRUCTURE.md:3–21` 统计 1486 个查询内去重平台，其中 1199 个是纯终端平台；它不是正概率信念状态数量，更不是运行成本占比。七个关键根当前 ALIGHT 平台的候选数为 7、8、8、9、9、15、9，且仍有 2–5 项相关非动作观察。约简后两个根动作共享的评分车次仍为 8–12。

共同读到一个车次，也不意味着两臂可消去同一个值。最简单的同一救援车例子：

\[
Q_a=\mathbb E[\mathbf1\{A_a\le D\}g(D)
+\mathbf1\{A_a>D\}H].
\]

即便两臂使用完全相同的救援车变量 D，只要到达平台时刻 A 不同，就有

\[
Q_a-Q_b=\mathbb E[(\mathbf1\{A_a\le D\}-\mathbf1\{A_b\le D\})(g(D)-H)].
\]

真正差异发生在可赶上车的边界区间，不是“共享车次”本身可以取消。混合续程还叠加新选择、同车信息和 W 重选，因子图中的交互因此保留。这个例子只是说明耦合来源，不是本项目已建立的独立新定理。

## 5. 两个只读 profile 定位出三个具体成本

保持原 10 秒 CPU 上限，对 root 6/query8 与 root32/query39 的 cheapW 求值做 cProfile。所有 profile 开销也在预算内；环境和插桩会影响达到的工作进度，因此这两次不是新的配对性能结论，不能与旧回执比较胜负。cProfile 下列累计函数时间相互嵌套，不能相加为独占 CPU。

### root 6：W 评分历史重建与联合事件枚举并存

- 平台便宜动作比较 `priority.py:145 cheap`：累计约 4.55 秒。
- `PhysicalDecisionEngine._history`：约 4.13 秒；它为 action cache 键获取相关车次的 law/basis，调用 `PhysicalHistory.law`，会构造 emission、正向消息并检验支撑。
- `_joint_outcomes`：约 2.05 秒，其中 `_joint_trip_outcomes` 约 1.66 秒。
- 跨独立车次 `combine`：约 0.69 秒。
- 在该插桩轨迹只遇到 4 次 singleton 积分，未运行 terminal 子集 DP。

这不支持“只要优化终端 DP 就能救七根”的判断。进一步应记录每次观测新增了哪些本车约束、哪些 W scorer 真正变化，验证能否增量更新；不能假设删去所有旧历史或把 W 换成 P0 会保持原策略。

### root 32：混合事件生成和 terminal 都付出成本

- `_joint_outcomes`：约 3.11 秒，其中 `_joint_trip_outcomes` 约 2.40 秒。
- terminal 接口及其子集 DP：约 2.12 秒。
- terminal BOARD 重评分约 1.33 秒，WAIT 分数约 0.53 秒，已包括在 terminal 总时间内。

因此应对“混合平台瓶颈”和“终端子块瓶颈”分别实验，不能只用一个覆盖率解释所有状态。

### 一个确定的无效计算：最后一项观察之后还造条件链

`experiments/reconstruction_v52/reference.py:242–267` 逐个 cid 分裂 yes/no 并建立 `_ChainLaw`，最后只返回 `(probability, visible)`，把 child law 丢弃。若 `len(cids)==1`，分裂后的两个 child law 从未用于任何下一项条件概率计算。

这两个 profile 的 `same_trip_observation_groups` 都为 0，却分别建立 **17,626 / 26,088** 个 `joint_trip_conditionings`。单观察组可直接返回 p 与 1−p，无需构造两个 child law；多观察组最后一个 cid 也只需保留质量和可见标记。这是直接可验证的工程优化，不改变概率分布，不涉及删质量，也不具独立新颖性。

不能用 `_joint_trip_outcomes` 的总时间作为可节省时间承诺；它包含必要 marginal 求值等工作，真正节省需专门配对测量。

## 6. terminal 接入存在的可改进点及其证据边界

`priority.py:6–18` 明确：StructuralReference 先尝试终端积分，只有不适用才回到 ImpactReference。终端内核内部没有 impact screening。

`terminal.py` 的具体实现：

- 97–126 行先对全部候选计算完整 physical marks，再开始事件求和。
- 160–225 行局部 memo + 按本节点概率排序的 DFS；optimal 模式在 197 行先递归 WAIT，再与实际 BOARD 取最小。
- 228–268 行只对整个已完成平台跨调用复用；部分平台再次调用会新建 `_Terminal`，内部 physical/board/wait/memo 都重新初始化。

这是一个“局部块精确完成优先”的接口，不是全局根间隙优先。它保留所有未完成质量的合法区间，因此没有发现错误认证；但如果一个进入概率很低的末平台求和很贵，可能占掉更应花在其他混合分支上的时间。

可检验的工程替代是：将 terminal 返回值改成可恢复任务，持久保存 `(j,mask,d)` 的部分值与依赖，向宿主暴露质量加权根区间贡献与一次增量工作成本。是否有用必须按根最终区间、总耗时衡量，不能只数 terminal 完成率。它还需与普通 anytime DP/图搜索对照；可恢复调度原则本身不构成新 OR 方法。

重要限制：原回执中 root6/18/62 没准入 terminal，故此修复不可能单独解释或解决所有关键根的当前失败。

## 7. 下一步应如何使用这些诊断

### 第一步：重写诊断问题，保持研究主线关闭

下一轮问题应是“能否在完整配对设计下识别强便宜规则可改进的条件决策”，而不是“还能怎样把 0/88 做到 88/88”。先区分：真实已实现的单趟差值、冻结 P0 下的条件期望差、相对全因果最优的 regret。它们需要不同证据。

现有 full128 对 cheap 的 root4/root62 正例与 root6/root18/root32 负例应一起保留。单个回放世界的 335 秒收益或 263 秒损失不能认证条件期望动作方向；七个根也已经是开发状态，不能代替新的检验样本。

### 第二步：一次有限的参照修整，用于识别缺口

建议只做以下具体事项，完成后停止工具层滚动扩建：

1. 增加只求固定策略实际根臂的 API，并保留全部强制臂诊断为另一个付费任务。
2. 增加“仅根预界”参照，独立核算根预计算、首动作排除、固定策略值、terminal 子块的时间和界收紧贡献。
3. 消除单观察组及最后观察项之后不再使用的 `_ChainLaw`。
4. 记录 W 评分 history/law 重建、概率子集枚举、真正后续决策三项成本；只在证据显示主导时试增量更新。
5. 如需 terminal 改造，只试可恢复部分状态接口，与保持原接口的强对照配对，不扩预算。

每项都用有限世界真值或原始枚举验证区间包含、总质量、原 W 选择相同；新增测试针对具体失效风险，而非增加测试数。

### 第三步：围绕真正差异事件进行缺口搜索

应先提出可证伪的机制候选，例如：两动作的到达平台窗口不同，导致相同救援车的可赶乘事件不同；早下车后观测的价值与继续乘车的时刻机会冲突；多步再次决策使固定 rolling surrogate 排序失真。按机制抽取完整共同历史的正负状态，分析有多大概率质量落在“动作会不同且损失会不同”的窗口。

可对确定的候选控制器做同一 P0 世界、各自只读合法历史的配对评估，先寻找条件期望改进证据。统计区间和确定性枚举区间必须分别标注；更少的未知并非新策略自动优于便宜规则。固定策略之间的检验通常不需要先把全最优值精确算出。

共同前缀取消、策略优势望远镜恒等式、标准 rollout、普通子集 DP 和每车鞅惩罚已在 V55 新颖性核查中有先例。真正可立项的结构贡献需证明一种新的可构造充分状态、可认证低成本的差值求值、或本问题特有的内层可解性，并展示它优于相应标准技术，而不是换名重做。

### 第四步：立项门槛

只有同时回答下面问题才继续深度重构：

- **决策缺口：** 哪种可观察状态中，强便宜策略系统性忽略什么？相同合法信息和真实成本下改善有多大，负例在哪里？
- **方法增量：** 哪条新命题或算法步骤是现有静态依赖、普通缓存、rollout、subset DP、信息松弛不能直接给出的？
- **净收益：** 在固定质量或硬时限下，方法的全成本是否优于已优化强基线，超限与失败是否计入？
- **外部证据：** 开发根之外的日期/工况，是否仍有可重复机制和效果？

如果参照修整后仍只能报告“同一值算得快一点”，就保留工程贡献，不再将其变成一条承诺 G2 的主算法路线。当前证据既不保证能通过 G2，也不证明便宜策略已最优。
