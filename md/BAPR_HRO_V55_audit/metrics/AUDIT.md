# V50–V55 数值与证据独立审计

固定版本：`a2b82be9c3fc6b61e2a5826d7cd8691d39ff4491`。本审计只读取提交中的原始收据，没有重新运行 1760 次 V55 求解、没有增加预算、没有重跑 1412 项项目测试。测试通过数属于提交的记录，不能当作本次独立重跑结果。

`recompute.py` 不调用项目的结果汇总函数，直接读取 4400 份 V53–V55 原始查询和 576 份 V51 整趟回放；独立重算值区间、完整 CPU、首次动作证书、初始边界贡献、策略类偏序下的后悔区间和配对差值。`extract_existing_banks.py` 是另一位审计者提供的只读脚本，重算 V51 全部 136 个 128 世界的配对 bank。输入摘要哈希保存在 `metrics.json`。

## 一、最重要的新发现：当前最优值结果主要来自初始化边界

V53 `reference.py::solve` 在完整 DP 之前构造每个根动作的 `root_bounds`：目的地松弛下界和有限条合法固定路线的承诺上界。对于最优值目标，初始根区间为：

\[
[L_0,U_0]=[\min_a L_a-\text{clock},\ \min_a U_a-\text{clock}].
\]

直接比较存盘 `root_bounds` 与最终 `value` 两端，得到：

| 实现/预算 | 最终根值两端完全等于初始边界 | 初始即可严格认证动作 | 最终严格动作证书 |
|---|---:|---:|---:|
| V53 impact / b2 | 88/88 | 30/88 | 37/88 |
| V53 impact / b10 | 88/88 | 30/88 | 40/88 |
| V55 strong / b2 | 88/88 | 30/88 | 38/88 |
| V55 strong / b10 | 84/88 | 30/88 | 40/88 |

认证严格采用源码条件 `upper(a) < min(lower(other)) - 1e-9`。另有 6 格初始仅边界相等，不能计为严格动作证书。这也是不能用非严格比较统计证书数的原因。

b10 的额外 10 个证书全部是 WAIT，query/root 为：7/5、19/15、22/17、36/29、47/39、56/47、60/50、63/51、66/53、81/65。其竞争动作下界得到改进，足以认证首动作；但根最优值的总区间没有进一步收紧。绝不能据此说整个 DP 无用，也不能将这些首动作证书解释为 cheap 的完整策略最优性。

V55 真正收紧根最优值的四格如下，均早在 V53 已认证 ALIGHT，且均不在原七个关键根中。

| query / root | V53 区间宽 | V55 区间宽 | V53 CPU | V55 CPU |
|---|---:|---:|---:|---:|
| 0 / 0 | 617.127 | 140.180 | 6.809 | 10.001 |
| 15 / 12 | 232.012 | 24.826 | 6.385 | 8.229 |
| 43 / 36 | 68.195 | 1.832 | 5.921 | 5.652 |
| 49 / 41 | 370.883 | 161.077 | 6.457 | 5.501 |

前两格质量提高但更慢，后两格质量和 CPU 同时改善。因此 4/88 是局部值参照改进，并不是四个新的真实决策缺口，也不是四个新增策略胜例。

**初始化不是免费。** `_prepare`、目的地下界与承诺路线搜索都计入完整 CPU；承诺搜索最多每动作 16 条路线，且受查询 CPU 的约 15% 初始化上限控制。收据没有分别记录这些阶段的 CPU。上述统计不能用于声称“零成本已经取得 30 个证书”，也不能直接减去一个臆造的初始化成本。

## 二、CPU 改善的来源需要按停止原因理解

V55 b10 optimal 的平均 CPU 从 7.598590 降到 6.257735 秒，88 格合计净省 117.995271 秒，数值成立。但新子问题的状态计费与原一般 DP 状态并不是等成本操作。

| 配对分组 | 格数 | 合计净省 CPU | 占全部净节省 | 相同首动作/认证标签 | 所有动作区间也相同 |
|---|---:|---:|---:|---:|---:|
| V55 达 20000 状态，根值两端不变 | 58 | 122.097 秒 | 103.48% | 58 | 54 |
| 其中：V53 未达状态帽、V55 达状态帽 | 8 | 42.614 秒 | 36.12% | 8 | 6 |
| 其中 root32 和 root57 | 2 | 14.853 秒 | 12.59% | 2 | 0 |

103.48% 并非算错：其余 30 格合计净慢约 4.102 秒。第二行的 8 格 query 为 26、34、39、71、79、82、83、85；全部仍没有严格动作证书。

root32 的最优值查询从 10.002 秒变为 2.614 秒，V55 的 20000 计费状态中 18263 是 `terminal_dp_states`；root57 从 10.001 秒变为 2.535 秒，其中 17940 是终端 DP 状态。两根最终最优值区间、所选 CONTINUE 与未认证状态都相同，但 ALIGHT 上界分别变松 16.701 和 20.638 秒。

这部分结果可以表述为“在相同声明预算下，以更少 CPU 返回了相同的根最优值区间”。它尚未表明以更少计算完成了原来未完成的整体策略任务，也不保证所有动作区间质量相同。不能通过将异构状态计数都叫 20000，直接推导相同工作量或同质量完整任务加速。详细停止计数及原收据路径见 `optimal_cpu_attribution.json`。

## 三、最优值参照改善没有转化为完整策略证据

以下都是 b10、同一 88 状态、V53 强 impact 对照与 V55 strong 的原始单查询结果。“宽度”是计算未解区间宽，不是策略的真实损失。

| 目标 | V53 宽度 | V55 宽度 | V53 CPU | V55 CPU | 窄/宽/平格数 |
|---|---:|---:|---:|---:|---:|
| 最优值 | 289.992 | 279.080 | 7.599 | 6.258 | 4 / 0 / 84 |
| cheap P0 | 1021.943 | 1266.203 | 8.936 | 8.995 | 25 / 35 / 28 |
| cheap W | 1685.427 | 1859.605 | 9.166 | 9.172 | 21 / 52 / 15 |
| P0 一步改进 | 707.981 | 974.279 | 8.933 | 8.987 | 34 / 31 / 23 |
| P0 两步改进 | 1154.551 | 1329.702 | 9.440 | 9.350 | 49 / 39 / 0 |

P0/W 区间变宽说明相同预算内对固定目标知道得更少，不表示策略行为或实际旅行损失恶化。V55 没有新增在线策略，V51 的实际回放收益不变。

本审计先将 P0 与一步查询中同一强制首动作、同一 P0 续程的已付费动作区间取交集，分别重建它们不同的根策略值，再独立通过策略类偏序 `V* <= V2 <= V1 <= V(P0)`、`V* <= V(W)` 传播五个已付费区间；只在合法根证书成立时使用 `V1 = V(P0)`。没有跨版本混用区间，没有直接把 P0 整体值与一步整体值当作同一目标。结果复现：

| b10 五查询合并结果 | V53 impact | V55 strong |
|---|---:|---:|
| 平均每状态总 CPU | 44.075 秒 | 42.762 秒 |
| P0 完整后悔的平均上界 | 1043.934 秒 | 1260.720 秒 |
| W 完整后悔的平均上界 | 1704.418 秒 | 1869.882 秒 |
| P0 后悔上界 ≤60 秒 | 14/88 | 15/88 |
| W 后悔上界 ≤60 秒 | 7/88 | 6/88 |
| P0 后悔上界 ≤300 秒 | 28/88 | 25/88 |
| W 后悔上界 ≤300 秒 | 11/88 | 7/88 |
| P0/W 完整后悔严格为正或严格为零 | 0/88 | 0/88 |

所有 88 格 P0/W 完整后悔仍为 `[0, 正上界]`；这是未解，不是最优。23 个 `P0 = 一步` 证书只识别同一续程下首步改进值，不识别 `P0 = V*`。

## 四、终端分解命中了容易的子问题，但未覆盖核心计算

结构清单中 1199/1486 个独特平台符合终端 DP 条件，占 80.69%。这个分母是输入菜单结构数量；它既不是后验访问概率，也不是 CPU 占比，更不是未解区间贡献。

在 b10 的实际 P0 查询中，41/88 格完全没有准入任何终端 DP；W 为 46/88。W 的 46 格中 31 宽、10 窄、5 平；有终端准入的另外 42 格仍是 21 宽、11 窄、10 平。故不能把完整策略值问题的失败单归因于“还没接入终端子问题”。

原七个关键根对应的根 ALIGHT 平台都是混合续程；候选数分别为 7、8、8、9、9、15、9。语义约简后的根动作共享车次数仍为 8、9、9、12、12、11、10，存在未消除的同车/评分/后续观察耦合。

| root (query) | W 旧宽度→新宽度 | V55 W CPU | 终端准入次数 | 终端状态数 |
|---|---:|---:|---:|---:|
| 4 (5) | 1492.574→1865.619 | 10.021 | 4 | 0 |
| 6 (8) | 2193.474→2316.197 | 10.012 | 0 | 0 |
| 18 (23) | 1952.677→2275.231 | 10.097 | 0 | 0 |
| 32 (39) | 2304.243→2448.510 | 10.006 | 8 | 2052 |
| 57 (71) | 2299.556→2465.530 | 10.002 | 7 | 1997 |
| 62 (76) | 2024.036→2047.399 | 10.001 | 0 | 0 |
| 63 (77) | 2200.237→2184.273 | 10.003 | 9 | 4043 |

root4 的准入是单例等积分特例，没有真正展开终端 DP 状态。root6/18/62 的 W 求值至预算截止根本没有进入该内核。即便 root32/57/63 进入，前两者仍变宽，只有 root63 略缩 15.964 秒。

计数还显示，b10 optimal 平均约 10961 个终端 DP 状态，而 P0/W 只有约 512/502。分解覆盖的是不同目标下不同的实际搜索位置；最优参照上的局部省时不能外推为固定策略求值的净收益。

**现有收据不足以做精确 CPU 归因。** 它们保存状态、机会分支、积分与缓存次数，没有每个子程序的独立 CPU 计时。不能说某一理论耦合“占了 X% CPU”；也不能单凭状态数反推出终端 DP 使 P0/W 变宽的全部原因。要回答具体内核瓶颈，应在原查询上增加小规模、完整计费的分阶段 profiling，区分准备、cheap 排序、条件化、转移、积分、归约与界传播，再决定是否有改造价值。

## 五、此前已经做完的排查不宜再次包装为新方案

- V50 已完成窄/宽菜单 × 原生/共同观察的 2×2 拆分。该 72 根中观察口径本身没有改变损失，20.181 秒均值收益来自扩大可行动作菜单。不是仍需从头做的建议。
- V51 已在共同宽菜单和观察下比较八个控制器。cheap、single、pair、one_step 全部为 1390.750 秒，mean 为 1399.208；full128 与 matched128 均为 1392.375，2 胜 3 负 67 平。普通 rollout 在这批真实回放中尚无平均优势。
- snapshot CSA 有 root39 缺失 `163:departure`，完整 72 根的均值只能报告 `[1371.458,1421.458]`，不能拿完整 71 根均值与其他 72 根比较。
- V53 已加入强 impact 调度与缓存修复；其纯局部 cutoff 停止问题在 V54 已做过额度回流与逐级降低阈值。V54 的所有最终查询仍触及 CPU 或状态预算，不能再把“再降低 cutoff/再回流”当作未经检验的新突破。
- V55 最初普通调度结果确实不足以比较，后来已经补齐强 impact 控制。strong 保留 V53 的 0.01 impact 规则，没有集成 V54 reflow；这不是隐瞒，但也不能假设把两者简单相加便能弥补根任务不足。
- V55 保留了目标节点遮罩和 nominal scorer 的反例；其到达目标支配只在已证明的条件下成立，不能扩大为所有 scoring target 都可删去后续依赖。

## 六、已有资料提供了比“再做完整最优 oracle”更直接的缺口入口

V51 full128 的 136 个 gate bank 保存了强制 ALIGHT/CONTINUE 首动作、随后执行原 shallow cheap π 的 128 个配对损失。源码 `rollout.py::evaluate` 的普通分支使用 `SnapshotExecutor(method='rolling_fixed', waiting='combined')`，远程未来消息冻结，局部观察仍模拟。

这不是完整在线 full128 策略的价值。在线 full128 会在后续 gate 重新规划；不能拿这些 bank 直接当作整趟动态 rollout 的反事实分布。

重新提取保存的数据发现 13 个改动作 gate、分布于 11 根：2、4、6、14、15、18、26、32、40、51、62。按已有样本的描述性正态区间，有 11 个 gate 的方向与 cheap 有差异且近似区间不跨零；root2/40 的改动信号不稳。真实整趟损失只有五根非零：root4 +335、root62 +96；root6 −263、root18 −145、root32 −140，符号以 cheap 减 full128 为正收益。

因此，应区分三层证据：

1. 保存的开发 bank 表明存在一些 **模型内、特定历史、强制首步后 cheap 续程** 的候选优势；它们足以提出可检验的问题。
2. 这些 bank 参与过动作选择，13 个候选也是从同批开发结果筛出来，区间不是独立确认或多重比较后的有效证书。
3. 五个真实回放非零值不是所有候选决策缺口；一个真实世界中没改变终点损失，不等于条件期望上没有区别。相反，某些模型内强信号对应实际负例，提示需要区分抽样噪声、模型误差、信息口径与后续重新规划。

下一轮不应要求先精确求出整个 `V*` 才允许检验 cheap 非最优。合法 challenger 的独立配对优势已经足够构成下界：如果同一历史、同一物理法则与同一可见信息下，有一个可实施策略 π' 满足 `V(cheap_W)-V(π')>0` 的有效证据，则 cheap 非最优不需要知道 `V*`。但 ordinary rollout / Monte Carlo / 耦合消差本身并不由此变成独立方法创新。

具体可执行的取证顺序应是：冻结上述候选历史与 challenger 定义；明确首步偏离一次后续 cheap，还是后续持续重新规划；用未参与选动作的新配对世界验证模型内优势；另外在未反复调参的新日期检验真实质量及成本；将模型内与真实数据外推分开报告。只有可重复的决策缺口通过后，才围绕影响该差值的未解分支研究结构性算法。原七根中的 root57/63 不能因为历史上重要就长期占据全部算法设计资源。

## 七、对 G2 的诊断边界

本次数值复算没有发现汇总值伪造或将失败样本删除。核心问题是：已经证明的局部约简与当前决定 G2 的整体任务不重合；不断提高参照值求解器的局部效率，还没有证明强便宜策略在真实决策上有足够稳定、足够重要的可改进空间。

同时，多个求解器的“0 个完整后悔证书”只是计算能力不足，既不能证明 cheap 最优，也不能证明该问题需要一项新的 OR 算法。G2 仍缺独立的决策缺口证据、相应的方法增量，以及在相同完整任务/信息/质量口径下的成本收益。当前证据支持停止把这套终端分解继续发展为论文主算法；它仍可保留为已验证组件及强对照。

## 复算入口

```bash
BAPR_HRO_REPO=/path/to/BAPR-HRO python recompute.py
BAPR_HRO_REPO=/path/to/BAPR-HRO python extract_existing_banks.py
```

- `metrics.json`：4400 查询与 576 回放的聚合、初始界贡献、七根明细、结构分组与输入哈希。
- `paired_raw_recomputed.csv`：V55 strong 对 V53 impact 的 880 组独立配对差值。
- `optimal_cpu_attribution.json`：b10 optimal 全 88 格的 CPU、状态停止、动作区间及原始来源。
- `existing_bank_signals.json`：V51 全 136 gate 的配对均值、标准误、描述性区间与实际整趟结果；禁止作为新验证实验引用。

所有 CPU 是提交中的单次历史计时，不是本次新测量；本审计不包含对真实总体风险校准、新日期泛化或 OR 独立新颖性的证成。
