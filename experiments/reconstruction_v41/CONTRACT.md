# V41 换乘与动作发布合同

科学回放沿用 `reconstruction_v34.discover.context` 的 `gtfs_station_max`：同站使用已有 GTFS 站内声明的最大适用换乘时间，HB 为 420 秒、Hardbrücke 为 180 秒；无官方站内声明时保留原图的 120 秒假设。所有方法共用同一图、菜单、消息和换乘值，不按结果调整。该站级保守合同不是已识别实际车辆站台对的步行时间。

现有档案给出公共消息和实际运行端点，没有真实车门开关或乘客端行动接收确认。主科学回放继续使用理想公共事件动作合同，计算 wall 不叠加到已等于发车时刻的事件上。真实硬截止应用暂不立项；不从未来实际端点生成“已公开”的行动窗口。

发布器单独使用显式声明的模型窗口做真实线程测量。`ActionToken` 指定动作集合、来源与单调 wall 区间 `[opens_at, closes_at)`；零宽或已过期窗口拒绝发布。`publisher.request(token, fallback)` 先同步写入外部 `updates` 通道；`request.start(compute)` 才启动后台，`compute(submit)` 的候选经独立通道检查实际接收时间。`request.current()` 不等待计算；外部执行器在窗口内调用 `take()`，原子消费当前指令，此后不能替换。到期但未消费的旧指令不能追认为及时执行。

`request.finish()` 仅在执行之后回收结果并完整计费，不能作为行动首次可用时刻。晚到候选仍保留回执，工作继续结束并计入 worker CPU / wall；跨截止的单段 CPU 只能给出晚工作上下界，总 CPU 不丢弃。进程跨度已包含 worker 与并发消费者，不能再加一次 worker CPU。一次性图、消息、seed manifest 加载由服务调用方在请求外完成、单列费用；每次后验、候选准备、提交检查与执行器成本仍由调用方整趟账本计费。所有 cheap / rollout 享有相同发布能力。线程接口不承诺操作系统硬实时调度。

本地具备 `md/GPT_diagnosis_v7.md`。其中链接的新增 15 页 Word 与独立复核材料未在仓库找到；现有旧诊断 docx 与 GTFS / 投稿 zip 不是该附件。本阶段使用本地代码、数据和可复现收据施工，未下载附件。
