# V41 物理条件链

版本为 `V41_exact_integer_anchor_finite_chain_v1`。保留 V34 的路线参数、行车/停站/间隔增量、服务状态转移和原有限格点。真实整数秒观测不在当前支持中时，复用 `EvolvingTripBelief` 的锚点构造，将观测残差平移格点和精确钟加入有限支持并重建有序转移。所有方法使用这一新版本；V40 投影模型结果不改写。

给定已固定的物理基底，每条车次的联合质量为

\[
 p(x_{0:L}\mid H)\propto \pi(x_0)\prod_{j<L}K_j(x_j,x_{j+1})
 \prod_j e_j(x_j;H).
\]

其中原核在 `t[j+1] < t[j]` 时严格为零；硬观测的 emission 只允许该精确时刻且车辆运行，未见窗口只排除窗口内运行状态。预测使用既定 V35 参数及 V36 单消息选择规则。前向后向评分与 FFBS 抽样消费同一个 `_ChainLaw`，故已知时刻为内部点质量，未来发车不可能早于已知到站。`CheckingWorld` 只检查锚点相等，绝不覆盖抽样时刻；没有 clamp、重抽或丢弃不兼容世界。

抽样前为全部相关车次建立物理基底。`clone()` 共享不可变基底；后续抽出的 own 事件已在该支持上，只重新施加观测/预测 likelihood，不再细化网格。在消息选择不变时，这就是同一有限链的精确条件化。预测重选沿用既定规则，不声称它来自一个已证明的联合消息生成模型。真实新 off-grid 观测引起的网格细化是显式模型近似更新，不能称作旧 V40 离散先验的严格 Bayes 条件化。

同 raw history 可能源于不同基底构造历史，因此完整续程状态还须保留基底上下文。`basis_context()` 返回进程内 `(trip, id(base))`；clone 保持其身份。规划器节点和转移缓存也区分基底，禁用旧 `prior_future` 原支持捷径。跨状态原始公开记录仍全部保留。

定向验证包含小链完整枚举与边际/采样比较、精确 off-grid 锚点与非倒序、同基底后续条件核、未见窗口及取消质量、消息重选、评分/抽样共用条件核、矛盾证据显式拒绝及原始快照恢复。此修复证明内部物理支持闭合，不证明现实校准或方法新颖性。
