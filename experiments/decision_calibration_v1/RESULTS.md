# 新日期与站台证据核查

**现有来源中合格未开发日期为 0，独立概率核验未启动；G2 未通过，也没有新增深度求解器重构的依据。** 本轮完成日期曝光／可用性核查、验收规则固定、全部已有事件的计划站台对核验。V41 模型、新菜单、信息条件及 MCT 均未改动。

本地及三台服务器 `jtl110gpu2`、`jtl110gpu`、`jtl311linux` 的已知项目源与归档目录已检查。确认 44 个真实数据已用日期；本地 35 个原始 GTFS-RT 包全在其中，服务器具名铁路端点缓存也都是已用日期。另有 07-18 至 07-22 的旧周端点缓存，但没有对应 RT 消息。V3 的 11-09 至 11-14 只是生成的伪日期，不被误算为真实数据曝光。49 个已考虑日期及逐项排除理由在 `date_selection.json`；目标 14 日，已选 0 日，日期尚未冻结。服务器只返回小清单和旧表头，CSV 正文／checkpoint 拉取为 0。

`acceptance_rules.json` 在任何新目标值打开前固定：四种联合事件的平均校准偏差容忍度为 ±2 个百分点；按共享车次事件和日期聚合，以整日重采样区间作预先声明的等价性筛查，保留全部缺测界。区间完全落入容忍带才通过，完全超出才判不通过，其余为未解；不足 14 日不通过验收。2 个百分点是本研究的筛查容忍度，相当于每 50 个机会允许一个事件的系统性计数偏差，不是旅行损失保证。等价性检验不能用“不显著”替代；聚类也须保留。[NIST 等价性说明](https://nvlpubs.nist.gov/nistpubs/TechnicalNotes/NIST.TN.2106.pdf)、[Census 分析准则](https://www.census.gov/about/policies/quality/standards/standarde1.html)。

利用保留的车次与站序回接静态表，1712 个键全部唯一恢复计划站台。580 个已登记开发事件的上下游共 **1160 对**全部保留：**490 对显式 MCT 与固定值一致，670 对同一站台标识没有适用规则，确认冲突为 0**。GTFS 只有真实 `location_type=1` 父站规则能继承；裸 `8503000` 是 type0 子 stop，不能把它到 `41/42` 的记录当作 `41/42→41/42` 的规则。[GTFS transfers 定义](https://gtfs.org/documentation/schedule/reference/#transferstxt)。
