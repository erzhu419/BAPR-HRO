# V42 已有轨迹中的结构机会

只读取 V41 两个基策略各 **148 × 128 = 18,944** 个配对世界，不重新运行策略或更改模型。脚本为 `opportunity_audit.py`，全部逐状态分母和实例保存在 `opportunities.json`。

| 几何筛查 | 原物理便宜策略 | 浅层尾值策略 |
|---|---:|---:|
| 完整入口菜单、入口钟相同的配对 | 165 / 18,944 | 150 / 18,944 |
| 覆盖固定状态 | 5 / 148 | 5 / 148 |
| 入口合并最多跳过第二臂决策 | 26 | 0 |
| 当前事件、完整剩余菜单相同的配对 | 1,430 / 18,944 | 1,397 / 18,944 |
| 覆盖固定状态 | 24 / 148 | 22 / 148 |
| 事件合并最多跳过第二臂决策 | 1,456 / 91,008 | 1,397 / 90,559 |
| 可匹配世界的整个第二臂 CPU | 6.336 / 109.562 秒 | 6.370 / 107.154 秒 |

入口筛查独立复现 V41 的 91,860／91,770 个检查点。所有入口几何匹配都有同一个最终直达登乘；事件筛查的所有已保存后缀也恰好相同。入口比较保留原菜单；事件比较删除当前车已驶过的路径／出口，平台保留整个菜单，只比较当前钟。两者均故意不检验历史，故只是机会筛查，**不是可用于提前停止的会合证书**。

原始事件轨迹中的相同 cid 或 stop 还不充分：完整未来菜单不同，后续决策仍可能不同。也不能从本批后缀恰好相同反推永久等价。逐事件的未来相关证据闭包是更合理的候选，但它最多跳过约 1.6%／1.5% 的当前决策；上表 5.78%／5.94% 的 CPU 比例已把可匹配世界的整个第二臂都算成可省，只是对这套几何判据非常宽松的已有费用上限。检查、证据投影、存表和轨迹恢复会进一步消耗这部分空间。

直达尾段确实存在：两组分别有 15,507／15,514 次直接终到乘车，涉及 20,395／20,379 个物理站段，之后决策数均为零。这支持在合法最后决策以后解析积分终值的实现方向，但仅有这项计数不能推断其收益：原规划器已经向量计算终端价值，省去物理读数不等于省去前面的规划；解析积分还会改变有限 bank 估计量，须与样本同一性的命题分开。

当前证据支持先测试逐事件、未来相关历史的精确会合，同时把收益预期限定在以上小范围内。它不能支持把“删去无关旧证据”本身作为新方法，也不能支持菜单交集直接相消。完整正负世界都留在上述分母中。
