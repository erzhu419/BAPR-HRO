# V38：完整续程同值提速，G2 仍未通过

固定 V37 模型、菜单、信息条件及原 128 世界种子，代码、理论、148 状态三档比较和 72 根在线配对均已完成。加速版相对本次完整 rollout 的整趟 CPU 降低 **11.86%**，旅行损失及全部动作轨迹不变。

| 同场、完整在线重算 | 平均整趟 CPU / 秒 | 平均截断旅行损失 / 秒 |
|---|---:|---:|
| 原完整 rollout，两动作独立缓存 | 1.17396 | 1404.86111 |
| 完整 rollout，仅共享缓存 | 1.16266 | 1404.86111 |
| V38 加速完整 rollout | **1.03474** | **1404.86111** |
| 六个强便宜控制，同用加速内核 | 0.04947–0.07758 | 1416.15278 |

六个控制是名义、组合、单目标、双目标、双目标一步改进和双目标链停止。V38 对每个控制仍是 **4 胜、2 负、66 平**，总改善 813 秒、平均 11.29167 秒；全部 72 根到达。正例 016/025/028/064 分别改善 145/468/184/258 秒；负例 057/063 分别恶化 146/96 秒，均完整保留。

V38 比仅共享缓存平均再省 **11.00%**；55/72 趟更快，17 趟更慢。148 个冻结状态的完整条件计算由 79.17570 降到 73.67463 CPU 秒，降低 6.95%；98 组更快、50 组更慢。缓存共享本身只减少约 0.96% 的整趟 CPU，不能把主要省时归因于缓存命中。

计算改写包括：唯一目的地出口的条件核改为向量前后推，主要矩阵运算由 O(LT³) 降为 O(LT²)；只生成所请求的 rolling_fixed 策略；批量插值与复用累积分布；同一 bank 两臂共享原有公开历史缓存。没有裁剪执行轨迹、丢弃后验信息或改成固定尾值。详见 [实现](planner.py)、[完整评价器](evaluator.py)、[理论](THEORY.md)。

三档 **444 组**条件评估逐世界复现原损失、状态、动作轨迹、决策计数和门选择；每档仍保留 1,891 个未解配对。**216 趟**完整 rollout 在线重放，各实际重新计算 139 个条件 bank；另完成 **432 趟**便宜控制重放。在线只从公开状态目录读取原种子，旧答案仅在计时结束后核对，答案复用次数为 0。[原始配对与逐根成本](summary.json) · [质量—耗时图](quality_cpu.png) · [冻结协议](protocol.json)

本次速度分母是同场重新执行的完整 rollout。旧 V37 的 1.02033 秒来自“实际执行加原回执费用”的计费方法，不作为本次提速分母。模型、采样、后验、全部续程、当前评分、状态匹配与种子目录加载全部计入在线 CPU；共同档案加载、图构建和实验结果写盘单列。单进程、BLAS 单线程，方法顺序按根轮换，没有重跑择优计时。环境见 [environment.json](environment.json)。

**732 项测试通过，16.70 秒。** 初期一次核验误报来自内存非出现区间元组与 JSON 列表的容器差异；统一表示后直接重验已保存结果，没有重跑世界。原报错和修复说明保留在 [failures](failures/diagnosis.json)。本阶段服务器传输为 0。

## 结论与下一步

已得到有实际净收益的同值实现优化，但仍是标准完整 rollout。加速版 CPU 仍为六个便宜控制的约 13–21 倍；本轮没有产生超出标准 rollout 的新结构求解结果，因此 **G2 整体仍未通过**。

下一步限于一次结构检验：在全部冻结状态上分解下车点、后续等待和沿途信息更新的耦合，找出固定尾值失效的条件及完整续程需要保留的最小状态。只有得到可推广的精确简化或必要计算量减少，才继续算法重构；若最后只是标准 rollout 较好，就收束这一算法路线。停止继续增加通用缓存、等待 DP 或证书变体来替代该判断。

## 边界

这些是既有六个开发日期和裁剪菜单上的同一批条件世界，重复执行不构成独立新样本。128 世界完整续程值仍是冻结当前消息的经验估计，不是总体精确积分或未来消息树最优值；未解质量区间不是总体置信或遗憾保证。每格仅一次配对计时，全部快慢案例保留；逻辑旅行时钟没有加入实测计算延迟。
